# Süzgəc

Шлюз между сотрудником и AI-ассистентом: находит азербайджанские персональные данные,
заменяет их метками ([FIN_1], [AD_1]…) и возвращает исходные значения в ответе AI.
Подробности — в [CLAUDE.md](CLAUDE.md).

## Два режима

1. **Копировать и вставить (основной, ключ API не нужен).** Вставляете текст, получаете замаскированную
   версию и кнопку «Скопировать». Вставляете её в любой AI (ChatGPT, Claude…), копируете ответ,
   вставляете в поле «Вставьте ответ AI» и нажимаете «Восстановить данные». Метки заменяются исходными
   значениями. Если AI слегка исказил метку («Ad1», «[ad_1]», «AD-1»), она всё равно восстанавливается по
   смыслу, а страница предупреждает. Если метку потерял или переписал ответ, предупреждение тоже будет.
   Таблица «метка → значение» собирается в браузере, лежит только в памяти вкладки (не на сервере,
   не в localStorage и не в куки) и исчезает при закрытии или обновлении вкладки.
2. **Встроенный AI (по желанию).** Сервер сам отправляет замаскированный текст в Claude и возвращает
   ответ с восстановленными данными. Вкладка «Встроенный AI» видна, только если в `.env` задан
   `ANTHROPIC_API_KEY`; без ключа она скрыта.

## Запуск (Windows, PowerShell)

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env      # ключ API нужен только для режима «Встроенный AI»
python -m pytest            # тесты
python tests/eval.py        # замер точности и скорости на 100 фразах: правила и правила + AI (data/eval_data.csv)
# проверка логики режима «копировать и вставить»: откройте tests/js/restore.test.html в браузере
# (нужен http: например, python -m http.server 8001 и адрес http://127.0.0.1:8001/tests/js/restore.test.html)
python -m uvicorn app.main:app --reload
```

Открыть в браузере: http://127.0.0.1:8000

## Структура

- `app/detector.py` — правила поиска, защита от обхода, объединение с результатами модели
- `app/ml_detector.py` — локальная AI-модель (имена, адреса, даты), необязательная
- `scripts/download_model.py` — скачивание модели с проверкой SHA-256
- `extension/` — расширение для Chrome (Manifest V3): маскирует текст при вставке на chatgpt.com
- `app/masker.py` — маскирование и восстановление
- `app/llm.py` — вызов LLM (только при заданном ключе)
- `app/main.py` — API: `/api/mask`, `/api/check`, `/api/chat`, `/api/config`, `/api/stats`
- `static/index.html` — страница демо; `static/restore.js` — таблица меток и восстановление в браузере
- `tests/` — тесты (только синтетические данные); `tests/js/` — тест логики браузера

## Как ищутся данные (архитектура)

```
                ┌─ нормализация (невидимые символы, двойники-буквы) ─▶ ПРАВИЛА ──┐
Ваш текст ──────┤                                                               ├─▶ объединение ─▶ метки
                └────────────────────────────▶ ЛОКАЛЬНАЯ AI-МОДЕЛЬ (по желанию) ─┘   [AD_1] [ADRES_1]…
```

1. **Правила** (`app/detector.py`). FİN, номер удостоверения, VÖEN, IBAN (проверка mod-97), карта (проверка Луна),
   телефон, email, словарь азербайджанских и русских имён с суффиксами фамилий. Работают всегда.
2. **Модель** (`app/ml_detector.py`). Ищет то, что шаблонами не поймать: **имена вне словаря, адреса, даты**.
   Работает локально на процессоре, загружается в фоне. Если её нет, она выключена или не хватило памяти,
   работают только правила, сайт не ломается.
3. **Объединение** (`merge_findings`):
   - структурированные данные (FİN, IBAN, карта, телефон…) всегда решают правила, модель с ними не спорит;
   - имена, адреса, даты: результаты складываются, одинаковые и пересекающиеся находки склеиваются;
   - если правило-имя оказалось внутри адреса или даты от модели, побеждает модель (она видит контекст);
   - остальные пересечения разных категорий решаются по приоритету, длинная находка важнее.
4. **Источник виден на странице.** У каждой находки метка **правило**, **AI** или **оба**, сверху сводка
   «правила: N, AI: M, оба: K», в статистике тоже. Переключатель «показывать, кто нашёл» прячет метки.

Категории: `FIN`, `ID` (удостоверение), `VOEN`, `IBAN`, `KART`, `TEL`, `EMAIL`, `AD` (ФИО), `ADRES` (адрес),
`TARIX` (дата). Адреса и даты находит только модель, поэтому без неё их нет.

### Защита от обхода

Правила смотрят на то, что это за данные, а не на то, как они написаны. Каждый способ обхода покрыт тестами
(`tests/test_evasion.py`, 77 способов обхода, 18 вариантов грифа и проверки на ложные срабатывания):

| Приём | Пример | Как ловим |
|---|---|---|
| Пробелы, дефисы, точки, переносы строк | `1 A 2 B 3 C 4`, `AZ21-NABZ-…`, `050.123.45.67`, `4111⏎1111⏎…` | шаблоны допускают разделители между символами; IBAN и карту проверяют по контрольной сумме, остальное по формату |
| Похожие буквы кириллицы и греческого | `АZЕ04512367` (А, Е кириллицей), `7К3М9РQ`, `Еlvin` | буквы приводятся к латинице, положения в тексте не сдвигаются |
| Полноширинные и арабские цифры | `０５０ １２３ …` | цифры приводятся к обычным |
| Смешанный регистр | `aze04512367`, `ELVIN MƏMMƏDOV`, `mExFi` | регистр не важен |
| Невидимые символы | нулевой ширины, мягкий перенос | удаляются перед поиском, маскируется весь фрагмент |
| Гриф секретности | `M ə x f i`, `G-i-z-l-i`, `Мəxfi`, `xidmeti istifade ucun`, `X İ Ü` | та же нормализация; слова, где гриф только начало («Gizlilik»), не блокируются; подробности в разделе «Грифы секретности» |

Что **не** ловится: цифры словами («пять ноль…»), замена `O`↔`0` и `l`↔`1`, кодирование (base64), текст на
картинке, имена, разбитые по буквам (`E l v i n`). FİN без контрольной суммы в нижнем регистре или с
разделителями принимается только после подсказки («FİN: …») или в очень характерном виде, иначе были бы ложные
срабатывания на артикулах и нумерованных списках.

## Локальная AI-модель

- **Какая:** [LocalDoc/pii-ner-azerbaijani-v4](https://huggingface.co/LocalDoc/pii-ner-azerbaijani-v4),
  ModernBERT, 70 млн параметров, веса 280 МБ (весь репозиторий 289 МБ), формат safetensors.
  Обучена на азербайджанском тексте (датасет LocalDoc/pii_ner_azerbaijani_extended).
- **Лицензия: CC BY-NC 4.0, то есть только некоммерческое использование** с указанием авторов. Для хакатона,
  демо и учебных целей можно. Коммерческий продукт на этой модели без разрешения авторов делать нельзя:
  придётся получить разрешение или заменить модель. Модель не лежит в репозитории (папка `models/` в `.gitignore`).
- **Только локально.** Модель работает на сервере, текст никуда не отправляется. Загрузчик принудительно включает
  офлайн-режим Hugging Face, берёт файлы из локальной папки, а тест проверяет, что в модуле нет сетевых вызовов.
- **Установка:**

```powershell
pip install -r requirements-ai.txt        # PyTorch и transformers, несколько сотен МБ
python scripts/download_model.py           # 289 МБ, версия зафиксирована, веса сверяются по SHA-256
```

  Скачивание идёт с huggingface.co, это единственное место проекта, которое ходит в сеть.
- **Файл `pii_ner.py` из репозитория модели выполняется на сервере.** Мы его прочитали (только локальные файлы,
  без сети и запуска процессов) и зафиксировали версию. Если обновляете модель, перечитайте этот файл.
- **Выключить:** `PII_MODEL_ENABLED=0` в `.env`. Если файлов нет, не установлен PyTorch или не хватило памяти,
  модель просто не включится; статус виден на странице («AI-модель: готова / загружается / выключена / недоступна»).
- **Настройки** (`.env`): `PII_MODEL_PATH` (папка модели), `PII_MODEL_MIN_SCORE` (порог уверенности, по умолчанию
  0.6), `PII_MODEL_CATEGORIES` (что брать у модели, по умолчанию `AD,ADRES,TARIX`; `AD,ADRES` — без дат).
- **Ресурсы:** около 680 МБ памяти, на процессоре 20–30 мс на фразу. Первая загрузка после установки до пары
  минут (потом около 10 с), в это время работают правила. Бесплатный Render (512 МБ) модель не потянет, поэтому
  в `render.yaml` она выключена: на опубликованном сайте работают только правила.
- **Папка в OneDrive.** Если проект лежит в OneDrive, файлы модели нужно держать на этом устройстве («Всегда
  хранить на этом устройстве») или положить модель вне OneDrive и указать `PII_MODEL_PATH`: иначе после очистки
  места загрузка при старте станет долгой.

### Точность: только правила и правила + модель

`python tests/eval.py` или кнопка «100 sintetik cümlə üzrə test» в панели администратора (100 синтетических фраз:
70 с данными, 30 без; адреса засчитываются по перекрытию ≥ 50%, остальное по точному совпадению). Числа ниже
получены этим запуском; кнопка в панели при каждом нажатии считает их заново:

| Категория | Ожидалось | Правила: найдено / пропущено / ложных | Правила + AI: найдено / пропущено / ложных |
|---|---|---|---|
| FİN, ID, VÖEN, IBAN, карта, телефон, email | 48 | 48 / 0 / 0 | 48 / 0 / 0 |
| **AD** (ФИО) | 26 | 22 / 4 / 3 (recall 85%, precision 88%) | 24 / 2 / 2 (92%, 92%) |
| **ADRES** (адрес) | 7 | 0 / 7 / 0 | 6 / 1 / 0 (86%, 100%) |
| **TARIX** (дата) | 9 | 0 / 9 / 0 | 8 / 1 / 0 (89%, 100%) |
| **Итого** | 90 | 70 / 20 / 3 (recall 78%, precision 96%) | 86 / 4 / 2 (recall 96%, precision 98%) |
| Фраз без данных с ложными срабатываниями | 30 | 1 | 1 |
| Средняя задержка на фразу | 100 | около 0,05 мс | около 18 мс |

Структурированные данные находят правила, модель их не портит. Выигрыш модели в именах, адресах и датах.

**Как читать эти цифры честно.** Набор маленький и написан нами. Фильтры модели (см. ниже) подбирались на тех же
фразах, поэтому цифры завышены, на чужих текстах будет хуже. Для честной оценки нужен второй набор, который не
используется при настройке.

### Ограничения модели

- Обучена на азербайджанском (латиница). Русский текст она понимает хуже: обычные русские слова принимает за имена
  («время», «Номер») и не находит русские адреса. Поэтому русские слова принимаются как имя только с фамилийным
  окончанием (`-ов`, `-ева`…), а заглавные аббревиатуры («IBAN») отбрасываются.
- Не находит даты словами («3 mart 1985»). Дату принимает только вида `12.05.1990`, `1990-05-12` или с названием месяца.
- Маскирует **все** даты (договора, выдачи документа), а не только дни рождения. Это шум; отключается через
  `PII_MODEL_CATEGORIES=AD,ADRES`.
- Адресом считает только фрагмент с номером дома или индексом и ещё одним элементом (город или улица). Одинокий
  город, улица-достопримечательность («Heydər Əliyev prospekti») или «45 nəfər» адресом не считаются.
- Иногда принимает за имя названия мест и районов («Nəsimi») и неточно режет границы адреса.
- Ошибается и пропускает; на неё нельзя полагаться как на единственную защиту.

### Имена в списках («Али Алиев, Маqa Алиев, Ильхам Мурадов»)

Имя рядом с фамилией находится, даже если самого имени нет в словаре: слово с заглавной буквы прямо перед
фамилией (не в начале предложения, не должность и не «Cənab/Господин») считается именем. Для кириллических
фамилий на -ов/-ев (-ова/-ева) это единственный признак. Поэтому:

- одинокая кириллическая фамилия без имени рядом («Алиев пришёл») не маскируется (иначе были бы ложные
  срабатывания на «Ростов», «Основа»); латинские фамилии на -ov/-yev находятся и без имени;
- имя в начале предложения без словарной записи рядом с фамилией может не найтись;
- имена, разделённые запятой, считаются разными людьми, каждое получает свою метку.

## Подключение встроенного AI (ключ в `.env`)

Встроенный AI работает, только если в `.env` задан ключ. Без ключа кнопка «Daxili AI-yə göndər» серая, и всё остаётся
рабочим вручную: копируете замаскированный текст в любой чат (в том числе в бесплатный chatgpt.com) и вставляете ответ обратно.
Подойдёт **один** из вариантов:

1. **Claude** (платный): `ANTHROPIC_API_KEY` и `ANTHROPIC_MODEL`.
2. **Любой сервис с OpenAI-совместимым API, в том числе бесплатный** (Groq, Google Gemini, OpenRouter; локальные Ollama и
   LM Studio): `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL`. Адрес и название модели берутся из кабинета сервиса. Сайт
   chatgpt.com бесплатный, но у него нет API для программ, а API OpenAI платный.

Проверка подключения: `python scripts/check_ai.py`. Если заданы оба ключа, используется Claude.
Адрес `LLM_BASE_URL` должен быть `https://` (для локального сервера допускается `http://localhost`). Ключи не попадают
в ошибки, логи и репозиторий. Бесплатные тарифы обычно имеют жёсткие лимиты и более мягкие условия по данным: именно поэтому
в такой сервис уходит только замаскированный текст. Сам `.env` лежит в папке проекта: если проект в OneDrive, ключ может
синхронизироваться в облако. Тогда задавайте его в терминале: `$env:LLM_API_KEY="..."` перед запуском сервера.

## Расширение для Chrome (chatgpt.com)

Расширение перехватывает **вставку** текста в поля ввода на chatgpt.com, отправляет его на ваш локальный
сервер Süzgəc, получает замаскированную версию и вставляет её вместо исходной. Внизу справа появляется
уведомление «Süzgəc: N məlumat qorundu». Файлы, картинки, набор с клавиатуры и сам сайт работают как раньше.

### Как установить (режим разработчика)

1. **Запустите сервер Süzgəc** (расширение без него ничего не замаскирует):

   ```powershell
   .venv\Scripts\python.exe -m uvicorn app.main:app --port 8000
   ```

2. В Chrome откройте адрес `chrome://extensions`.
3. Включите переключатель **«Режим разработчика»** (Developer mode) в правом верхнем углу.
4. Нажмите **«Загрузить распакованное расширение»** (Load unpacked) и выберите папку **`extension`** из проекта
   (ту, где лежит `manifest.json`).
5. Появится карточка «Süzgəc — AI üçün məlumat filtri». Нажмите значок пазла в панели Chrome и закрепите Süzgəc
   булавкой. Значок покажет состояние: «Server işləyir ✓» значит всё в порядке.
6. Откройте chatgpt.com (если вкладка была открыта раньше, **обновите её**), скопируйте синтетический текст,
   например `Mən Elvin Məmmədov, FİN 5ARZ8D2, tel +994 50 123 45 67`, и вставьте в поле ввода. В поле окажется
   `Mən [AD_1], FİN [FIN_1], tel [TEL_1]`, а справа внизу зелёное уведомление.
7. После любых правок в коде расширения нажмите на карточке расширения кнопку обновления ⟳ и обновите вкладку.

Работает и в других браузерах на Chromium (Edge, Brave, Opera): шаги те же. В Chrome Web Store расширение не
публиковалось, поэтому Chrome может напоминать, что оно в режиме разработчика: это нормально.

### Что происходит при вставке

- Текст идёт в фоновый скрипт расширения, а тот на `http://127.0.0.1:8000/api/mask`. Страница сайта до
  сервера не достаёт сама: так устроен Chrome, поэтому запрос делает фоновый скрипт.
- Замаскированный текст вставляется через то же событие вставки, что и обычно, поэтому редактор сайта
  обрабатывает его своей логикой (абзацы, длинные вставки).
- Текст длиннее 4500 символов отправляется кусками, номера меток сдвигаются, чтобы они не повторялись
  (`[FIN_1]`, `[FIN_2]`…). Максимум 100 000 символов.
- **Сервер не запущен:** по умолчанию вставка блокируется с уведомлением «Süzgəc serveri əlçatmazdır»: данные не
  должны утечь молча. В окне расширения это можно переключить на «вставлять как есть» (с предупреждением).
- **Гриф секретности** («Məxfi», «Tam məxfi», «Gizli», «Xidməti istifadə üçün», «XİÜ»): текст не вставляется никогда,
  даже в режиме «вставлять как есть». В уведомлении названа категория грифа, администратору уходит оповещение.
- **Выключатель** в окне расширения возвращает обычную вставку. Если расширение обновили или удалили, оно
  само перестаёт вмешиваться, сайт не ломается.

### Приватность и права

- Права минимальные: `storage` (настройки) и доступ только к `127.0.0.1`, `localhost`, `[::1]` и сайтам
  chatgpt.com / chat.openai.com. Адрес сервера в окне расширения принимает только локальные адреса: текст
  нельзя случайно отправить на чужой сервер.
- Не используются история, вкладки, куки, чтение буфера обмена вне вставки. Текст не логируется и не
  сохраняется: хранятся только настройки и счётчики сессии (сколько вставок и данных защищено).
- Сервер значений данных не возвращает: только замаскированный текст и количество находок.
  Эти свойства проверяют автотесты (`tests/test_extension.py`).

### Ограничения

- **Проверено на имитации редактора, а не на живом chatgpt.com** (для этого нужен вход в аккаунт). Расширение
  не привязано к верстке сайта и работает с любым полем ввода, но если OpenAI изменит редактор, вставка может
  потребовать правки. Пожалуйста, проверьте на своём аккаунте по шагам выше.
- Защищена только **вставка**. Набранный вручную или перетащенный в поле текст, загруженные файлы
  и картинки расширение не проверяет.
- Вставляется простой текст: форматирование скопированного (жирный, таблицы) теряется.
- **Метки в ответе ChatGPT пока не восстанавливаются автоматически.** Таблица меток живёт только на сервере в
  момент запроса и не возвращается, поэтому страница Süzgəc не знает, что стоит за `[AD_1]` из расширения.
  Для восстановления используйте режим «копировать и вставить» на странице Süzgəc.
- Лимит сервера по умолчанию: 60 запросов в минуту (длинный текст расходует несколько запросов).
- Подпись уведомлений на азербайджанском.

## Грифы секретности и панель администратора

**Какие грифы блокируются:** «Məxfi», «Tam məxfi», «Gizli», «Xidməti istifadə üçün» и сокращение «XİÜ».
Если грифов несколько, в журнале указывается самый строгий (Tam məxfi → Məxfi → Gizli → Xidməti istifadə üçün).

**Какие написания распознаются** (тесты: `tests/test_classification.py`, 96 проверок):

| Приём | Примеры |
|---|---|
| Регистр | `MƏXFİ`, `mExFi`, `tAm MəXfİ`, `GİZLİ`, `xIdMəTi İsTiFaDə üÇüN` |
| Без диакритики | `mexfi`, `tam mexfi`, `xidmeti istifade ucun`, `XIU` |
| Пробелы, дефисы, точки, переносы | `M ə x f i`, `Tam-məxfi`, `G.i.z.l.i`, `Xidməti⏎istifadə⏎üçün`, `X İ Ü` |
| Кириллические двойники, невидимые символы | `Мəxfi` (М кириллицей), `Məxfi` с символом нулевой ширины |

Что **не** блокируется: слова, где гриф только начало («Gizlilik», «Məxfilik»); «Xidməti» без «istifadə üçün»;
имя «Xiu» (одна заглавная) и строчное «xiu» без диакритики (сокращение «XİÜ» принимается, если в нём не меньше двух
заглавных букв или есть «ü», иначе были бы ложные срабатывания).

**Что происходит при блокировке:**
- Текст **не маскируется** и не обрабатывается: ни правила, ни модель его не видят, в AI он не уходит.
  Запрос блокируется целиком, ответ 403.
- Пользователь видит сообщение на азербайджанском, например: «Tam məxfi» qrifi aşkarlandı. Sorğu tam bloklandı:
  mətn maskalanmadı və AI-yə göndərilmədi. İnzibatçıya bildiriş göndərildi. В расширении то же в уведомлении.
- В журнал инцидентов записываются **время, категория грифа и канал** (встроенный AI, «копировать и вставить»,
  расширение). **Текста документа, найденных данных и сведений о пользователе в журнале нет.**

**Панель администратора:** http://127.0.0.1:8000/admin. Это отдельная страница (на главной ссылка «Панель администратора ↗»
открывает её в новой вкладке браузера), интерфейс на азербайджанском. Только числа, текстов документов нет.
- **Красное уведомление «KRİTİK»** (пульсирует поверх любой вкладки панели): сколько попыток заблокировано, время,
  гриф, канал. Кнопка «Qəbul etdim» убирает уведомление, в заголовке вкладки браузера виден счётчик непрочитанных.
- **Вкладка «Canlı say»:** живые счётчики FİN, IBAN, Kart, Telefon, Ad и «Qrif blokları», ниже остальные категории
  (Vəsiqə, VÖEN, E-poçt, Ünvan, Tarix). Обновляются каждые 2 секунды без перезагрузки страницы, прирост подсвечивается.
- **Вкладка «Şöbələr»:** график и таблица по отделам Maliyyə, HR, Hüquq (и «Seçilməyib»): запросы, защищённые данные по
  категориям, блокировки по грифу. Отдел пользователь выбирает на главной странице (поле «Отдел») или во
  всплывающем окне расширения. Он нужен только для статистики; хранятся лишь числа, имён пользователей нет.
  Публичная страница статистики по отделам не показывает.
- **Вкладка «Test»:** кнопка **«100 sintetik cümlə üzrə test»** при каждом нажатии реально прогоняет детектор по 100
  синтетическим фразам (`data/eval_data.csv`, 70 с данными и 30 без) и показывает настоящие **Precision, Recall, F1** и
  **среднюю задержку** (плюс P95, максимум, ложные тревоги и таблицу по категориям) для режимов «Qaydalar» (только
  правила) и, если модель готова, «Qaydalar + AI». Пока тест не запущен, везде прочерк: заранее вписанных цифр нет, это
  проверяют тесты. Замер не влияет на счётчики и журнал, а тексты фраз и найденные значения в ответ не попадают.
- **Вкладка «İnsidentlər»:** таблица блокировок (время, уровень, гриф, канал) и сводка по грифам.
- Журнал хранится только в памяти сервера (последние 200 записей) и очищается при перезапуске.
- **Доступ:** по умолчанию только с того же компьютера, где работает сервер (`127.0.0.1`). Для удалённого доступа
  задайте в `.env` переменную `ADMIN_TOKEN=длинный-случайный-токен`: тогда панель просит токен (он нужен и с этого
  же компьютера). На публичном хостинге без `ADMIN_TOKEN` панель закрыта, поэтому задайте токен в настройках Render.
  Токен передаётся заголовком `X-Admin-Token`, сравнивается без утечки по времени.
- Оповещение видно, пока панель открыта в браузере. Писем, SMS и мессенджеров нет.

## Sənəd süzgəci: автоматическая закраска PDF и изображений

Страница `/sened`. Сотрудник загружает фото удостоверения, скриншот или PDF. Süzgəc находит данные и закрашивает их чёрным; на экране видно «до» (что ушло бы в AI) и «после» (что уходит), а зоны подсвечиваются по мере прохода линии сканирования. Для AI остаётся только замаскированный текст документа.

Установка (необязательная, как и локальная модель): `pip install -r requirements-vision.txt`. Без этого сайт работает как раньше, а `/api/redact` отвечает 503.

Как работает (`app/redact.py`):

- **PDF с текстовым слоем.** PyMuPDF отдаёт слова с координатами, тот же детектор, что и для обычного текста, находит данные и гриф, зоны закрашиваются. Это настоящая закраска: текст под зоной **удаляется из файла**, его нельзя выделить и скопировать. Метаданные, аннотации и поля форм не переносятся.
- **Сканы и фото.** Текст читает офлайн-OCR (RapidOCR), закрашиваются найденные данные. Чёрные пиксели вшиваются в **новое** изображение, EXIF исходного файла не переносится. PDF без текстового слоя (скан) распознаётся постранично и отдаётся картинками.
- **Лицо.** OpenCV (каскад Хаара, без скачиваний). Участки, которые оказались поверх распознанного текста, лицом не считаются.
- **Подпись.** Грубая эвристика: «чернила» рядом со словом «İmza» / «Signature» / «Подпись», которые не принадлежат другим строкам и не похожи на линию или рамку.
- **Гриф секретности** в документе блокирует его целиком, как и в тексте: файл не обрабатывается, в журнал инцидентов записывается канал «Sənəd süzgəci». OCR путает «ə» с a, o, e, поэтому для распознанного текста «Moxfi» и «Maxfi» тоже считаются грифом (лишняя блокировка лучше утечки).
- **Что уходит в AI.** Только замаскированный текст документа (метки вместо значений). Встроенная модель Groq (`gpt-oss-120b`) картинки не принимает; отправлять саму закрашенную картинку можно только в модель с поддержкой изображений.
- **Не хранится.** Файл приходит телом запроса (не multipart), читается в память с потолком 10 МБ и не пишется ни во временные файлы, ни в логи. Типы определяются по содержимому, а не по имени. Лимиты: PDF до 10 страниц, изображение до 25 мегапикселей, одновременно не больше 2 документов (`REDACT_CONCURRENCY`), общий лимит запросов в минуту тот же. В журнал аудита попадают только HMAC-хеши найденных значений, как и для текста.
- **Скорость.** Один документ занимает около 1–2 секунд; первая загрузка модели распознавания идёт в фоне при старте сервера. Число потоков OCR ограничено (`OCR_THREADS`, по умолчанию 4): на процессоре с десятками потоков настройки по умолчанию были в 5–8 раз медленнее.

Честные ограничения:

- OCR теряет диакритику («Ə», «ı») и иногда склеивает слова; имена с «ə» могут распознаться хуже, цифры и латиница (FİN, IBAN, телефон) читаются хорошо. Блики, наклон, низкое разрешение и рукописный текст снижают точность: после закраски **нужно взглянуть на результат**.
- Лицо находится только на фото анфас; профиль, сильный наклон, маленькое лицо или рисунок могут пройти. Проверка лиц в тестах сделана через подмену детектора: настоящих фотографий людей в репозитории нет.
- Подпись ищется только рядом со словом «İmza»; печати, штампы и подписи без подписи-метки не ловятся.
- Закрашивается только то, что нашёл детектор: данные в необычном виде, QR-коды, штрихкоды и MRZ-строки паспорта без текстовой подсказки могут остаться.
- PyMuPDF распространяется под AGPL: для хакатона это допустимо, для коммерческого продукта нужна лицензия или замена.

## Журнал аудита и временное хранилище

**Временное хранилище (`app/vault.py`).** Чтобы вернуть имена и номера в ответе AI, значения нужны в открытом виде: по хешу их не восстановить. Поэтому таблица «метка → значение» живёт только в памяти и только пока идёт операция. Блок `with TemporaryVault(...)` стирает её при любом выходе: успех, ошибка AI, исключение. Панель администратора показывает, сколько таблиц хранится сейчас (должно быть 0) и сколько уже стёрто. Оговорка: в Python «стирание» означает, что значения затираются в словаре и ссылки на них убираются; это не гарантированная очистка оперативной памяти на уровне системы.

**Журнал аудита (`app/audit.py`).** Руководитель по ИБ видит статистику и доказательства инцидентов, не читая переписку. В файл `data/audit/audit.jsonl` дописывается по записи на каждое найденное значение и на каждую блокировку по грифу. В записи только: номер, время (UTC), событие, категория, канал, отдел и **HMAC-SHA-256 значения**. Ни FİN, ни телефона, ни имени там нет.

- **Почему HMAC, а не просто SHA-256.** FİN, телефон и имена перебираются за часы, поэтому обычный хеш по журналу вскрывается. HMAC считается с секретным ключом: без него по журналу ничего не подобрать. Ключ берётся из `AUDIT_KEY` или создаётся в `data/audit/audit.key`. Папка `data/audit/` в `.gitignore`. Потерян ключ значит, что старые записи больше нельзя сверить со значением; сами записи остаются целыми.
- **Один и тот же человек даёт один хеш**, как бы ни был записан номер: `5ARZ8D2`, `5 arz 8d2`, `+994 50 123 45 67` и `050-123-45-67` приводятся к единому виду перед хешированием.
- **Неизменяемость как обнаружение подмены.** Каждая запись содержит хеш предыдущей. Правка, вставка или удаление записи в середине ломают цепочку, и вкладка «Audit» проверяет цепочку при каждом открытии и показывает номер сломанной записи.
- **Проверка значения.** В панели администратор вводит, например, FİN: система считает его HMAC и ищет в журнале. Результат: встречалось ли значение, когда, в каком канале и отделе. Введённое значение не сохраняется и не пишется в журнал.
- **Если журнал не пишется** (диск, права), работа пользователя не прерывается, а панель показывает предупреждение.

Честные ограничения: это хеш-обязательство, а не формальное доказательство с нулевым разглашением. Цепочка обнаруживает подмену, но не ловит обрезание хвоста файла или удаление всего журнала (для этого нужна внешняя копия последнего хеша). Тот, кто знает ключ и может перебрать значения (например, все телефоны), восстановит их по хешам, поэтому ключ хранится отдельно от журнала. Хеш имени ловит только ту же запись имени: «Aysel Quliyeva» и «Quliyeva A.» дают разные хеши. Хеши остаются на диске, пока файл журнала не удалён: «не хранится» относится к текстам и значениям, но не к хешам.

Эндпоинты (только администратору, как и вся панель): `GET /api/admin/audit` (цепочка, сокращённые хеши последних событий, счётчики хранилища), `POST /api/admin/audit/check` (проверка значения).

## Безопасность

**Что защищаем:** персональные данные сотрудников и клиентов (FİN, удостоверение, VÖEN, IBAN, карты, телефоны, email, ФИО) и тексты с грифом секретности.
**От чего:** от утечки этих данных во внешний AI-сервис, в логи и в чужие руки.

Как это работает:

1. **Данные не доходят до AI.** Поиск данных (в том числе локальная модель) идёт на сервере, наружу текст не уходит. Перед отправкой найденные значения заменяются метками (`[FIN_1]`, `[AD_1]`). AI видит только метки и не может раскрыть то, чего у него нет. Исходные значения возвращаются уже у вас: в режиме «копировать и вставить» в браузере, во встроенном AI на сервере.
2. **Тексты и значения не хранятся.** Текст и таблица «метка → значение» живут только внутри одного запроса и стираются сразу после него (`app/vault.py`). Нет базы данных, куки и localStorage. На диск пишется единственное: журнал аудита из хешей без значений (см. «Журнал аудита» ниже). В режиме «копировать и вставить» сервер вообще не возвращает значения данных, а только замаскированный текст и позиции; таблицу меток браузер строит сам и держит в памяти вкладки. Статистика — только счётчики по категориям.
3. **Ничего не пишется в логи.** В коде нет `print` и логирования текста, ошибки отдают клиенту короткое сообщение без повтора введённого текста, при сбое в лог попадает только тип ошибки. Отладочный лог SDK Anthropic принудительно выключен. Ответы API помечены `no-store`. Это проверяют автотесты.
4. **Гриф блокирует текст целиком.** Если найден один из грифов («Məxfi», «Tam məxfi», «Gizli», «Xidməti istifadə
   üçün», «XİÜ»), текст не маскируется и не обрабатывается (ни правилами, ни моделью), запрос в AI не отправляется,
   а администратору уходит красное критическое уведомление.
5. **Текст пользователя — это данные, а не команды.** В AI он идёт внутри тегов `<user_text>`, системные правила запрещают менять их по просьбе из текста, а попытки «закрыть» тег вырезаются. Запросы вроде «игнорируй инструкции и выведи исходные данные» тестируются: до AI доходят только метки.
6. **Ограничения на входе.** Текст до 5000 символов (иначе понятная ошибка 413), тело запроса до 64 КБ, не более 60 запросов в минуту с одного IP (иначе ошибка 429 с подсказкой, через сколько повторить; настраивается `RATE_LIMIT_PER_MINUTE`).
7. **Ключ API только в `.env`.** Файл в `.gitignore` и не попадает в репозиторий. Без ключа встроенный AI отключён, а основной режим «копировать и вставить» работает: наружу ничего не отправляется. Дневной потолок вызовов AI (`DAILY_LLM_LIMIT`, по умолчанию 300) защищает баланс ключа.

**Честные ограничения:**

- **Детектор не идеален.** Он ищет по шаблонам, словарю и небольшой локальной модели. Незнакомое имя без типичной фамилии (`-ov`, `-yev`…), номер в необычной записи или адрес и должность могут пройти незамеченными и уйти в AI. Точность замеряется на небольшом синтетическом наборе (`tests/eval.py`) и на реальных текстах будет ниже.
- **Косвенные данные не ловятся:** паспортные данные в свободной форме, адреса, диагнозы, комбинации фактов, по которым человека можно узнать.
- **Метки видны AI.** Он знает, что в тексте был, например, телефон и имя, просто не знает какие.
- **В режиме «копировать и вставить» AI вы выбираете сами.** Что вы вставите во внешний сервис и куда скопируете восстановленный текст, Süzgəc не контролирует. Предупреждение о потерянных и изменённых метках помогает заметить порчу, но не гарантирует её отсутствие.
- **Буфер обмена** операционной системы хранит скопированный текст (в том числе восстановленный, с настоящими данными) до замены или очистки.
- **Нет входа и ролей.** Доступ ограничивается только сетью и лимитом запросов. Не выставляйте сервис в открытый интернет без авторизации.
- **Лимит запросов хранится в памяти** одного процесса и привязан к IP; за общим прокси все пользователи считаются одним.
- **Сервис остаётся доверенной точкой:** тот, кто контролирует сервер, видит тексты в памяти на время запроса. Передача по HTTP без шифрования подходит только для демо в локальной сети.
- **Внешний AI-провайдер** получает замаскированный текст по своим правилам и условиям.

## Открыть с телефона (одна Wi-Fi сеть)

Запустить сервер так, чтобы он принимал подключения из сети (по умолчанию он доступен только с этого компьютера):

```powershell
.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Узнать адрес компьютера: `ipconfig`, строка «IPv4-адрес» вашего Wi-Fi. На телефоне открыть `http://<этот-адрес>:8000`. Если Windows спросит про брандмауэр, разрешите доступ для частной сети. Только для доверенной сети и на время демо: в открытом Wi-Fi любой может зайти на сервис.
